# 里程碑与验收标准（milestone）

> 本文件定义 M1～M3 的**主要目标特性**与**可验收的验收标准**（尽量可度量/可执行）。
> 节奏遵循 [ADR-005](00-决策记录.md)（M1 先行再回看）；详细工作流见 [20-改进计划.md](20-改进计划.md)。
> 验收标准约定：`[ ]` 未完成 / `[x]` 已完成并验证。每个里程碑结束跑遥测报表 + 自检脚本，用数据佐证。

## M1 — 基座（双工具可用 + 可度量 + 能上手 + 原则正确）

**主要目标特性**
1. 跨工具落地（WS1）：Claude Code 与 Codex 都能发现并运行 Skill；`AGENTS.md` 为单一事实源；零依赖 `install.sh`。
2. 集中式遥测（WS5）：emit.sh → collector → report，使用即产生数据、统一收集。
3. 文档与分发（WS6）：README、分发部署指南、贡献指南；陈旧文件归档。
4. 原则修正（WS0）：多 Agent 拆分原则修正落到研究报告与计划；`methodology.md §7.1` 修订。
5. 治理（本轮新增）：决策记录、里程碑文档、docs 编号规范、各主要目录 AGENTS.md。
6. **SKILL 内容覆盖研究报告（ADR-016，核心）**：7 个 SKILL 嵌入探索→规划→执行、契约先行、会话起步检查+PROGRESS、plan-validate-execute、生成者≠评估者、验证回路。
7. **分发结构重构（ADR-015）**：解散 `skills/shared`、通用规则进目标项目 `AGENTS.md`、平台指南作项目级公共参考、软链默认项目级不覆盖。
8. **去 Python（ADR-013）**：移除 `project_state.py` 与 MCP；跨会话进展由产物派生 + 遥测事件。

**验收标准**
- [x] `install.sh --dry-run/真实` 在 `--tools claude,codex` 下为每个 SKILL 建**项目级软链**，部署 `project-template`（AGENTS.md/PROGRESS.md/.fpg/references），**同名不覆盖**；临时项目验证软链可解析、AGENTS 部署、references 软链可达、重装跳过已有。
- [x] 仓库与文档/脚本中**无 `project_state.py`、无 `pip install mcp`、无 MCP 配置块**；SKILL 前置检查改为产物派生、收尾更新 `PROGRESS.md` + 发遥测。
- [x] 7 个 SKILL 正文 < 500 行，平台指南以 `.fpg/references/*.md` 引用且目标文件存在；无 `shared/` 残留。
- [x] `cd telemetry && bun test` 全部通过（11 用例，含 milestone 维度）；事件 schema 增 `milestone`。
- [x] 端到端：起 collector → emit 在线入库 → 断网落盘缓冲 → 恢复补传 → report 产出非空报表。
- [x] `AGENTS.md`（仓库）为单一事实源、`CLAUDE.md` 指针；**目标项目 `AGENTS.md`**（project-template）承载通用约定 + 遥测埋点。
- [x] README/分发指南/贡献指南更新到新模型（项目级安装、去 Python）；`SKILL.md.deprecated` 已归档。
- [x] 研究报告 §5/§7 含"按上下文拆分、不按角色""生成者≠评估者""环境优于提示"；§4.4/§11/§14 已更新为遥测+产物模型；决策记录含 ADR-008..016。
- [x] `docs/` 文件功能分类+优先级编号、中文命名；`skills/`、`scripts/`、`telemetry/`、`docs/`、`project-template/` 各含目录指引。
- [x] `methodology.md §7.1` 修订：职责映射澄清、补拆分原则；§7.2 与 ADR-009 冲突已修；§7.3 独立评估；并行图上下文隔离注。
- [ ] **遗留（ADR-014）**：`init_project.py` / `generate_api_contract.py` 仍为 Python，M2 移植为 Bun 并修复脚手架 docs/docker 复制缺陷（G6）。

**度量基线（M1 末采集，作为后续对比起点）**

## M2 — 强制与工件（把遵从率从 ~30% 拉到 ~95% + 长程可恢复 + 可靠验收）

**主要目标特性**
1. 运行时强制（WS2）：用户项目的 pre-commit/CI 门禁、契约一致性校验；本仓库 `check_skills.py`。
2. 长程 Harness 工件（WS3）：会话起步检查、PROGRESS/feature-list、**生成者≠评估者的独立验证**、dev/init 脚本、ARCHITECTURE 地图、harness 最小化纪律。
3. 修复脚手架缺陷（G6）：`init_project.py` 正确收集 docs/docker 模板，并加测试。
4. **迭代治理规范（ADR-018 / E001）**：用户项目统一采用 Epic(E) → Sprint(S) → Task(T)；每级 `plan.md` 是唯一计划、直接子项清单、状态与耗时/token 指标真源。

**验收标准**
- [ ] 故意删测试 / 改契约：CI 门禁或 pre-commit 能**拦截并失败**（可复现）。
- [ ] 契约一致性校验脚本能在实现与 `openapi.yaml` 不一致时报错并指明差异。
- [ ] `check_skills.py` 能检出违规 SKILL.md（>500 行 / 缺 frontmatter / 引用嵌套 / 失效路径）。
- [ ] 新会话能据 `PROGRESS.md` 恢复上下文并先跑端到端冒烟，再开始新功能。
- [ ] 验收/回归在**独立上下文**完成（非写代码的同一 Agent 自评）。
- [ ] `init_project.py` 脚手架出的项目**包含 docs/ 与 docker/**；新增测试覆盖该路径且通过。
- [x] 新增 `project-template/references/iteration-governance.md`，并接入 `sprint-plan`、`sprint-develop`、`project-qa`；不新增独立 Skill，不新增同级 `INDEX.md`。
- [x] `sprint-plan` 能生成 E/S/T 编号、各级 `plan.md`、直接子项清单、并行边界、估计 token、开始/结束/等待耗时字段。
- [x] `sprint-develop` 能在 Task 启动和结束时更新对应 `plan.md`，回填实际 token、主动耗时、等待耗时、偏差原因和验证证据。
- [x] `sprint-plan` / `sprint-develop` 已接入关键路径规则：Must Deliver、Must Verify、Supporting、Backlog、quick check 合并、计划 token 10%-15% 闸门。
- [x] 每级 `plan.md` 已要求包含直接下级分解清单、关键路径和 Mermaid 前序依赖图，用于判断 Sprint/Task 是否可并行启动。
- [x] 下级清单状态统一使用中文状态，并明确规划、启动、阻塞、实现、验证、完成、搁置时的更新责任和回填位置。
- [ ] 遥测对比：相对 M1 基线，返工率不升、AC 通过率不降（趋势性，非绝对）。

## M3 — 栈扩展与运行时质量（TS+Bun 后端 + 多环境 + 可观测/HA）

**主要目标特性**
1. TypeScript+Bun 后端 guide 与模板，与 Java/Spring 并列；scaffold 增加 `backend-bun` 平台。
2. 多环境隔离（dev/test/staging/prod）：分层 `.env`、配置矩阵、切换脚本；多项目独立 compose/端口。
3. 本地开发友好：lockfile 依赖一致性、统一 API client 的请求/响应日志 + trace-id。
4. 运行时 HA/可观测/可扩展：健康/就绪探针、结构化日志、OpenTelemetry metrics/trace、优雅关闭、水平扩展。

**验收标准**
- [ ] `scaffold --platforms backend-bun` 生成可 `bun install && bun run` 启动的后端骨架。
- [ ] 两栈后端（Java/Spring 与 TS/Bun）均可本地一键运行，且 API 请求带 trace-id、可在日志中追踪。
- [ ] 四套环境配置可一键切换；secrets 不入库（`.gitignore` 校验通过）。
- [ ] 后端暴露健康/就绪探针与 metrics 端点；docker-compose 一键起完整可观测环境。
- [ ] 文档（backend 两栈 guide + deployment-guide）覆盖 HA/可观测/可扩展/优雅关闭约定。

## 里程碑闭环（每个里程碑结束）
1. 跑 `cd telemetry && bun run report --format md` 与（M2 后）`check_skills.py`，留存报表。
2. 召开迭代回顾（[ADR-009](00-决策记录.md)）：用观测指标评估本里程碑、识别改进项、必要时新增 ADR。
3. 更新本文件勾选项与 [20-改进计划.md](20-改进计划.md) 状态。
