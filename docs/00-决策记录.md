## ADR-001 工具范围：Claude Code + Codex 双支持
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 团队会同时使用多种 AI 编码工具；只面向单一工具会限制落地。
- **决策** 这套 Skill 必须在 **Claude Code 与 Codex** 上都可用；可引入 Skills-Manager 等开源分发工具支撑。
- **理由** 覆盖团队实际工具组合；`AGENTS.md`/`SKILL.md`/stdio MCP 均为跨工具标准。
- **影响** 以 `AGENTS.md` 为单一事实源；`install.sh` 同时配置两工具；细节差异需各自实测。

## ADR-002 技术栈范围
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 原仅 Java/Spring 后端，且缺多项目/多环境/可观测等长期维护能力。
- **决策** 后端覆盖 **Java/Spring 与 TypeScript+Bun**；并满足多项目管理、多环境隔离（dev/test/staging/prod）、本地开发友好（依赖一致性、独立运行、网络请求可观测）、运行时 HA/可观测/可扩展、可读性、CI+自动发布。
- **理由** 匹配团队真实技术栈与长期维护诉求。
- **影响** M3 落地（新 guide + 模板 + 环境规范）。

## ADR-003 度量：集中式遥测
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 需要在分发给所有成员后"使用即产生数据、统一收集"用于运营报表；本地日志无法集中。
- **决策** 独立的 `telemetry/` 集中式管线（emit.sh → Bun collector → Bun report），**不复用 Python MCP、不用本地日志**；语言仅 TS(Bun)+shell。
- **理由** 集中可汇聚、跨工具、零额外语言；与状态 MCP 解耦（状态记"是什么"，遥测记"发生了什么"）。
- **影响** 见 `30-度量指南.md`、`telemetry/`。

## ADR-008 多 Agent 拆分维度（原则修正）
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 补充材料（[多 Agent 何时/如何用](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)、[Anthropic harness-design](https://www.anthropic.com/engineering/harness-design-long-running-apps)、[OpenAI harness-engineering](https://openai.com/index/harness-engineering/)）指出：按角色/工作类型拆分会制造协调开销、交接丢上下文。
- **决策** 多 Agent **按可隔离的上下文拆分，绝不按角色/工作类型拆分**；先单 Agent，仅在"上下文污染/可并行/需专精"且有证据时才上多 Agent；生成者≠评估者；harness 随模型升级做减法。
- **理由** 降低协调开销与 token 成本（多 Agent 3–10x），提升验收可靠性。
- **影响** 研究报告 §5/§7 已更新；计划 WS0/WS3；待修订 `methodology.md §7.1`。注：遥测 `actor_role` 刻画**人类成员角色**，与此不冲突。

## ADR-009 保留迭代（Sprint）开发模式
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 基于对团队开发水平的评估，以及当前 AI 协作中存在的问题，暂不激进切换到纯交付驱动模式。
- **决策** **保留迭代开发模式，以 Sprint 作为最小交付周期**；每个迭代结束的回顾会**根据收集的迭代观测指标**（返工率、交付时长、AC 通过率、阶段周期时间等）评估并持续改进。
- **理由** 迭代节奏与团队现状匹配，且天然契合遥测度量与持续改进闭环。
- **影响** `methodology.md` 的 Sprint 流程保留；回顾会消费 `telemetry/` 报表；后续可随团队成熟度再评估是否调整（届时新增 ADR）。

## ADR-013 移除 project-state（去 Python 的状态机制）
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 项目决定不再使用 Python；`.project-state.json` + `project_state.py`(MCP) 是唯一带外部依赖（`mcp`）的 Python 组件。其"跨会话进度"职责可由两条腿替代。
- **决策** **删除 `.project-state.json` 与 `project_state.py`**。跨会话进展由：① SKILL 从**项目产物**（`docs/PRD.md`、`docs/sprint-N.md`、`PROGRESS.md`、git log）派生；② 把进展信息（user、role、time、skill、milestone、phase、duration 等）作为**遥测事件经 `curl` 统一收集**（可度量/可观测/可改进）。
- **理由** 去 Python、去外部依赖；进度可观测性并入遥测；功能连续性用真实产物（更符合"结构化笔记"实践）。
- **影响** 所有 SKILL 的"前置检查/持久化"段重写；移除 MCP 配置与 `pip install mcp`；遥测事件 schema 增 `milestone`。

## ADR-015 解散 skills/shared，SKILL 自包含 + 项目级公共文件
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 原 `skills/shared/` 把多 SKILL 共享内容集中，既不利于"SKILL 自包含"，也使单个 SKILL 难独立分发。
- **决策** **解散 `skills/shared/`**：①**所有 SKILL 通用**的条目 → **目标项目 `AGENTS.md`**（随项目统一分发）；②**平台指南**（backend/web/ios/android、api-design）→ **项目级公共参考**（`project-template/`，安装时部署进目标项目）；③ SKILL **专属**内容 → 各自 `references/`。交付物因此包含**目标项目 AGENTS.md 等公共文件**，不只是 SKILL + 遥测。
- **理由** SKILL 自包含、可独立分发；通用约定单点维护、随项目分发。
- **影响** install 为每个 SKILL 建**软链**（默认项目级 `.claude/skills`+`.codex/skills`，可选用户级），**同名不覆盖**（跳过并告警）；并部署 `project-template/` 公共文件到目标项目。

## ADR-017 工具侧 hook 自动埋点（M2 提前，Codex 优先）
- **日期** 2026-05-30 ・ **状态** 生效
- **背景** 指令式 emit（SKILL 内一行可选 bash）遵从率仅 ~25–40%，且实测发现 Codex/Claude 用的**非交互 shell 不读 `~/.zshrc`**，导致 `FPG_HOME` 缺失、埋点静默跳过——真实使用产生 0 数据。
- **决策** 把"工具侧 hook 自动埋点"从 M2 提前实现，**Codex 优先**：用 **Codex Hooks**（`<repo>/.codex/hooks.json` 的 `SessionStart`/`Stop`）与 **Claude Code hooks**（`<repo>/.claude/settings.json`）在会话/回合事件**自动**上报 `session_start`/`turn_complete`，不依赖模型自觉。
  - 统一脚本 `telemetry/hooks/tool_hook.sh <codex|claude>`：两工具 payload 均为 stdin JSON，一个脚本服务两者；脚本**自带环境**（自 `source ~/.fpg-telemetry/env.sh`，规避非交互 shell 问题）；**永不阻断**工具（始终 exit 0、无 stdout）。
  - **不用 Codex `notify`**：`notify` 仅单程序（已被 Computer Use 占用）、仅 `agent-turn-complete`、payload 无 `cwd`；Codex Hooks 支持多源共存、项目级、stdin 带 `cwd`。
  - `install.sh --wire-hooks` 自动写入两工具 hook 配置，**已存在则跳过不覆盖**。
- **理由** "使用即度量"必须可靠；hook 由 harness 强制触发，不靠模型记得（对应研究报告 §6"运行时强制 / 环境优于提示"）。
- **影响** 工具 hook 提供可靠**粗粒度**（会话/回合/角色/工具/项目/时长），SKILL 内 emit 仍提供 best-effort **细粒度**（阶段/Story/契约/AC）。遥测事件类型新增 `session_start`/`turn_complete`。
