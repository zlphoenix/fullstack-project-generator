# 分发与部署指南

> 如何把这套 Skill 分发给团队所有成员（Claude Code + Codex），以及如何部署集中式遥测，让"使用即度量"。

---

## 一、分发（让成员用上 Skill）

### 1.1 安装器（推荐，默认项目级、不覆盖、无 MCP）

```bash
bash scripts/install.sh --project-dir <项目路径> --tools claude,codex --dry-run   # 预览
bash scripts/install.sh --project-dir <项目路径> --tools claude,codex \
     --role <dev|product|qa|ops|pm> --telemetry-endpoint <收集器URL>              # 安装
```

参数：
- `--project-dir PATH`：目标项目根（默认当前目录）。
- `--scope project|user`：**默认 `project`**（装到 `<项目>/.claude/skills`、`.codex/skills`）；`user` 装到 `~/.claude`、`~/.codex`。
- `--tools claude,codex`、`--role`、`--telemetry-endpoint`、`--dry-run` 同义。

安装器做三件事（幂等、**不覆盖**）：
1. 为**每个 SKILL** 建**软链**到目标 `skills/` 目录；**同名已存在则跳过并告警**（不覆盖开发者已有 skill）。
2. **部署项目公共文件**：`project-template/AGENTS.md`、`PROGRESS.md` → 项目根（已存在不覆盖）；`references/` → `<项目>/.fpg/references`（软链，随仓库更新）。
3. 生成 `~/.fpg-telemetry/env.sh`（`FPG_HOME`、角色、遥测地址）→ 在 shell profile `source`。
> **无 MCP、无 Python 状态服务**（ADR-013）：跨会话进展由项目产物派生 + 遥测事件。

### 1.2 关键约束
- **必须保留完整仓库目录结构**：`skills/`、`scripts/`、`telemetry/`、`project-template/` 同级；路径以 `$FPG_HOME` 为准。
- **版本管理**：用 git tag 标记发布；团队统一拉同一 tag。契约/规范变更记 CHANGELOG。
- **FPG_TOOL 注入**：Claude Code 在 `.claude/settings.json` 的 `env` 加 `FPG_TOOL=claude`；Codex 在其 env 设 `FPG_TOOL=codex`。

### 1.3 工具侧路径参考
| 工具 | Skills 发现（默认项目级） | 项目指令 |
|---|---|---|
| Claude Code | `<proj>/.claude/skills/`（或 `~/.claude/skills/`） | 项目根 `AGENTS.md`（部署）；`CLAUDE.md` 指向它 |
| Codex | `<proj>/.codex/skills/` | 自动读项目根 `AGENTS.md` |

> 各工具的 Skill 目录约定可能随版本调整；以官方文档为准，必要时改 `install.sh` 的 `skills_target_dir()`。

### 1.4 可选：开源分发工具（调研结论）
- 当前默认 **零外部依赖**的 `install.sh` 足以覆盖双工具分发，**不引入**外部依赖。
- 若团队规模扩大、需要集中化的 Skill 版本/灰度管理，可评估 Skills-Manager 类开源工具作为 `install.sh` 的上层；其价值在统一升级与审计，代价是新增运维面。**建议先用 install.sh，规模化后再评估**。

## 二、部署集中式遥测

### 2.1 起一个收集器

```bash
cd telemetry
FPG_TELEMETRY_PORT=8787 \
FPG_TELEMETRY_DB=/var/lib/fpg/events.db \
FPG_TELEMETRY_TOKEN=<团队密钥> \
bun run collector
```

- 无状态 HTTP + 单文件 SQLite，可用 systemd / Docker / 任意 PaaS 托管，放内网即可。
- 健康检查：`GET /health`；即时指标：`GET /stats`。
- 鉴权：设了 `FPG_TELEMETRY_TOKEN` 后，`POST /events` 需带 `Authorization: Bearer <token>`（`emit.sh` 自动带 `FPG_TELEMETRY_TOKEN`）。

systemd 示例：
```ini
[Unit]
Description=FPG Telemetry Collector
[Service]
Environment=FPG_TELEMETRY_PORT=8787
Environment=FPG_TELEMETRY_DB=/var/lib/fpg/events.db
Environment=FPG_TELEMETRY_TOKEN=change-me
WorkingDirectory=/opt/fullstack-project-generator/telemetry
ExecStart=/usr/local/bin/bun run collector
Restart=always
[Install]
WantedBy=multi-user.target
```

### 2.2 出运营报表

```bash
cd telemetry
bun run report --db /var/lib/fpg/events.db --format md
bun run report --db /var/lib/fpg/events.db --format html --out /var/www/fpg/report.html
```

可用 cron 定时生成并发布到团队看板。

### 2.3 规模化
- SQLite 足以支撑中小团队；更大规模把 `telemetry/src/store.ts` 的存储边界替换为外部数据库即可（其余不变）。
- 隐私：默认只采流程元数据，不采代码/PII；成员可 `FPG_TELEMETRY_DISABLED=1` 退出。

## 三、用户项目的持续集成 / 自动发布

`project-deploy` Skill 会为生成的用户项目产出 `docker/` 与 `.github/workflows/ci.yml`（多阶段构建、非 root、健康检查、PR 自动测试）。
> 运行时强制（CI 门禁、契约一致性校验、覆盖率阈值）是 **M2（WS2）** 的增强项，见 [改进计划](20-改进计划.md)。

## 四、新成员上手清单
1. 安装依赖：`bash` + `curl`（必需）；`bun`（仅遥测后端）。M1 期间 `project-scaffold`/`project-architecture` 的脚本仍需 `python3`（M2 移植，见 ADR-014）。
2. 拉仓库（统一 tag），跑 `install.sh --dry-run` 预览后安装。
3. 在 profile `source ~/.fpg-telemetry/env.sh`，按角色设 `FPG_ACTOR_ROLE`。
4. 验证：`cd telemetry && bun test`（其余在目标项目中使用 Skill 时即时生效）。
5. 读 [README](../README.md) 的"使用方法"，在 Claude/Codex 里触发第一个 Skill。
