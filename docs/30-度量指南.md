# 度量指南：用数据验证规范的有效性

> 这套 Skill 的价值主张是"让 AI 辅助的团队开发更快、更一致、更稳定"。本指南定义**如何用客观数据验证它是否真的成立**，以及如何用数据发现瓶颈、持续改进。
> 实现见仓库 `telemetry/`（集中式遥测：emit.sh → collector → report）。

## 1. 为什么要度量

研究（DORA 2025）发现一个**"AI 生产力悖论"**：AI 大幅提升个体产出（任务 +21%、合并 PR +98%），但**组织级交付指标常常持平甚至变差**——吞吐 +2–18% 的同时稳定性下降、变更失败率上升。
**结论：不能只统计"生成了多少代码/多快"。** 必须同时跟踪质量与稳定性信号，否则"提速"是假象。

## 2. 核心指标

| 指标 | 定义 | 数据来源（事件） | 解读 |
|---|---|---|---|
| **返工率 Rework Rate** | `story_reopen / story_complete` | `story_reopen`, `story_complete` | **最关键的质量信号**。DORA 2025 仅 7.3% 团队 < 2%。持续上升 = 规范/契约没起到防错作用 |
| **Story 交付时长** | `story_complete.ts − story_start.ts`（avg/p50/p90） | `story_start`, `story_complete` | 衡量"需求→交付"速度；p90 反映长尾卡点 |
| **阶段周期时间** | 各阶段 `phase_complete − phase_enter` | `phase_enter`, `phase_complete` | 定位流程瓶颈（哪个阶段最耗时） |
| **AC 通过率** | `verification[kind=ac].ok / 全部` | `verification` | 验收一次通过的比例；低 = 需求/实现不对齐 |
| **契约变更次数** | `count(contract_change)` | `contract_change` | 契约稳定性；频繁变更 = 前期设计不足或需求漂移 |
| **角色/项目分布** | 按 `actor_role` / `project_id` 分组 | 全部事件 | 看哪些角色/项目在用、参与度如何 |

### 映射 DORA
- **变更失败率 ↔ 返工率**：本套用返工率近似（生产事故数据通常在团队既有系统中）。
- **变更前置时间 ↔ Story 交付时长 + 阶段周期时间**。
- 部署频率/恢复时间：建议与团队既有 DORA 工具结合，本遥测专注"开发流程内"信号。

## 3. 如何采集

1. **分发时配置**（`scripts/install.sh` 自动完成）：设置 `FPG_HOME`、`FPG_TELEMETRY_ENDPOINT`、`FPG_ACTOR_ROLE`、`FPG_TOOL` 等环境变量。
2. **使用即采集**：各 SKILL.md 在关键时机调用 `telemetry/emit.sh`（best-effort，离线缓冲，绝不阻断开发）。
3. **统一收集**：团队自托管一个 collector（`bun run collector`），所有成员事件汇聚到一处。
4. **出报表**：`bun run report --format md|html|json`，可定时发布到团队看板。

详见 `telemetry/README.md`。

## 4. 验证改进效果的方法（前后对比）

要证明"这套规范有效"，推荐 **A/B 或前后对比**：
1. **建立基线**：在引入/升级规范前，采集一段时期的返工率、交付时长、AC 通过率。
2. **引入变更**：分发新版 Skill（含契约强制、Harness 工件等）。
3. **对比**：相同口径再采集，看返工率是否下降、AC 通过率是否上升、p90 交付时长是否收敛。
4. **归因谨慎**：样本小时只看趋势不下定论；结合定性反馈（Retrospective）。

## 5. 重要约束（避免度量反噬）

- **度量用于发现瓶颈与验证规范，绝不作为个人绩效考核**。一旦考核，成员会优化指标而非优化结果（古德哈特定律 / 生产力悖论的微观版）。
- **只采流程元数据，不采代码内容/PII**；`actor_id` 用哈希后的不透明值；成员可 `FPG_TELEMETRY_DISABLED=1` 退出。
- **澄清**：`actor_role`（dev/product/qa/ops/pm）刻画的是**人类成员角色**，用于运营维度分析；它与"不要按角色拆分 Agent"（[ADR-008](00-决策记录.md)）是两件事，**不冲突**。
- **指令式埋点遵从率有限**（研究示纯指令约 25–40%）。若需接近完整采集，在 M2 用工具侧 hook 强制触发（见 `docs/20-改进计划.md` WS2）。当前 M1 的数据应理解为"采样"而非"全量"。
