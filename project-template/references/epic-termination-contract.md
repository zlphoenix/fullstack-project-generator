# Epic 终止契约与执行止损闸门

> 目的：防止 Epic 在自治/长程执行下从「拆解良好」滑向「永不收口的反刍循环」。
> 适用：每个 Epic 在 `sprint-plan` 创建时必须填写本契约，写入 `docs/iteration/epics/E###-*/plan.md` 的「终止契约」区块；`sprint-develop` 每次会话起步必须核对。
> 背景案例：见某 Epic 从 5 个 Sprint 失控到 27 个的复盘——根因是「只定义了如何开始，没定义何时停」。

## 1. 为什么需要

LLM 自治执行没有内建的「停」。面对一个无法跨越的障碍时，它会持续产出**看起来合理的相邻增量**（更多测试、更多脚手架、更多文档），把「动作」误当成「进展」。规划再好，若缺少**硬性终止条件**，循环不会自己结束。

闸门（gate）只是度量与判定，不是决策者，也不是 stop。`no-go` 本身不会让 agent 停下——没有终止契约时，它反而会去「刷绿闸门」，制造新的死循环。**终止契约是闸门之外、必须显式写死的停机条件。**

## 2. Epic 终止契约（开工前定义，不可中途放宽）

每个 Epic 的 `plan.md` 必须包含以下不可变字段：

```markdown
## 终止契约（不可中途放宽）

| 项 | 内容 |
|---|---|
| Definition-of-Done | <绑定真实用户可观测结果的一句话；mock/结构同构不可单独构成 DoD> |
| DoD 验收证据 | <哪一次真实/准真实运行、哪个命令、产出什么证据算数> |
| Sprint 预算上限 | <计划 Sprint 数>；硬上限 = 计划 × 1.2 |
| Token 预算上限 | <估计区间>；硬上限 = 上界 × 1.2 |
| 退出场景（必须全绿） | <列出构成 DoD 的真实用户流程，3–5 个> |
| 明确不做（out-of-scope） | <列出本 Epic 依赖但不负责证明的外部假设，如「服务端网关鉴权」> |
| 外部依赖与责任人 | <最硬的外部依赖（账号/环境/数据）+ 谁负责+ 截止判断点> |
```

规则：
- **DoD 必须绑定真实用户结果**。「结构同构」「单测通过」「mock parity ok」是必要条件，**显式声明它们不足以构成 DoD**。
- **out-of-scope 即不证明**。被划为外部假设的能力，本 Epic 不得为「证明它」开 Sprint。
- 契约一旦写定，放宽 DoD / 扩预算 / 把 out-of-scope 拉回范围，都需要**人类显式批准并记录原因**，不能由执行线程自决。

## 3. 预算熔断

- 实际 Sprint 数或累计 Token 触及硬上限（计划 × 1.2）时**自动 STOP**，进入人类 re-baseline，不得继续开新 Sprint。
- re-baseline 必须回答三选一：(a) 收口当前成果并把剩余转新 Epic/Backlog；(b) 砍范围达成原 DoD；(c) 经批准扩预算并记录依据。

## 4. 外部阻塞升级规则

当某 Task 阻塞于「执行者当前无法获得」的依赖（测试账号、受限环境、外部审批、第三方数据）：

- 该状态是**终态** `blocked-external`，不是「再想想办法」的提示符。
- **禁止派生相邻工作**去逼近它（不准为一个跑不了的测试造 preflight / evidence / safety gate / dry-run / 分类器）。
- 立即停止该线，写入 `PROGRESS.md` 未决问题，**升级给人类**，附：缺什么、谁能提供、不解决的影响。
- Epic 可在「该项标 blocked-external + 其余 DoD 达成」的前提下收口，把该项转 Backlog；不得为它无限期挂起整个 Epic。

## 5. 范围守卫（每个新 Sprint 必过）

开一个新 Sprint 前必须回答：**它推进 Epic 哪一条成功标准？**

- 追溯不到任何成功标准 → 拒绝立项。
- 追溯到的是「明确不做」清单里的项 → 拒绝立项。
- 只是「补一个之前报告说没覆盖的点」而该点不在 DoD 内 → 转 Backlog，不开 Sprint。

## 6. 自治执行 stop-gate（sprint-develop 每次会话核对）

- agent **不得自我授权** Sprint N+1；跨 Sprint 推进需人类确认或预先在契约中授权的批次边界。
- **无进展熔断**：连续 N 个 Sprint（默认 N=2）未改变「交付状态」（即没让某条退出场景从红转绿，只产出文档/测试/脚手架）→ 强制停，升级人类。
- **失焦自检**：每会话起步用一句话回答「本 Task 让哪个退出场景更接近全绿？」答不出 → 不是关键路径，停。

## 7. 闸门 no-go 归因（与发布闸门配合）

发布闸门报 `no-go` 时必须归因：

| 归因 | 含义 | 处理 |
|---|---|---|
| 内部可修 | 代码/契约/配置问题 | 正常修复后重跑 |
| 外部不可得 | 缺账号/环境/数据/审批 | 走 §4 升级，**不得用「再来一个 Sprint」消化** |
| 范围外 | 闸门在测一个 out-of-scope 项 | 修正闸门范围，不是修产品 |

**严禁**为了让闸门变绿而放宽契约、跳过负向场景，或把外部不可得伪装成「持续推进中」。

## 8. plan.md / PROGRESS.md 体现

- Epic `plan.md`：新增「终止契约」区块（§2）；Sprint 清单新增「追溯成功标准」列。
- `PROGRESS.md`：「进行中」必须标注「距 DoD 还差哪些退出场景」；出现 `blocked-external` 必须在「未决问题」置顶。
- 每个 Sprint 收口时在 Epic `plan.md` 记录「预算消耗 / 上限」，便于熔断判断。
